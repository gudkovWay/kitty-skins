# Wallpaper-driven system design
The wallpaper analysis is factual input, not a style reference to rewrite. Keep one coherent material, color, light and ornament grammar across applications; adapt density and geometry to each function. Explain bars, music/AI placement, negative-space usage and all meaningful exceptions with wallpaper facts and usability tradeoffs. Layout modes: style-only (retain topology), suggest-layout (propose without activation), auto-layout (design topology, never live apply). Artistic exploration/specification is independent. Primary selection is not approval or deployment. No generated commands, plugins or shaders. Runtime redraw never calls a model. Do not invent bindings, telemetry, native capabilities or approval.
